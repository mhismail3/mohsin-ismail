# mohsin-ismail: agent guide

This is Mohsin Ismail's personal site at https://mhismail.com, with a blog, a portfolio, and an About page. It's a React 19 + Vite 7 single-page app using BrowserRouter. Content is markdown in `public/`, bundled at build time, with prerendered per-route HTML for Open Graph tags. It's deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`.

**Pushing to `main` deploys the live site.** Work on a branch. Don't merge, push to `main`, or publish a post without Mohsin's explicit OK.

## Layout

```
public/posts/{YYYY-MM-DD-slug}/post.md       blog posts (+ images next to post.md)
public/projects/{slug}/project.md            portfolio projects (+ cover/gallery images)
public/about/about.md                        About page copy + gallery
drafts/{YYYY-MM-DD-slug}/post.md             private drafts: git-ignored, shown by `npm run dev` only, never built
src/data/{posts,portfolioProjects,about}.js  load + parse the markdown (import.meta.glob)
src/data/image-manifest.json                 generated by optimize-images (srcset/webp/blur); commit it
src/pages/                                   Home, BlogPage, PostPage, PortfolioPage, ProjectPage, AboutPage
src/components/{ui,features,layout}/         shared components (see guides/styling.md)
src/styles/                                  tokens.css + component/page CSS, all via index.css
scripts/                                     build + verification scripts (below)
guides/voice.md                              PRIVATE voice guide: git-ignored; canonical copy in
                                             ~/.tron/workspace/files/mohsin-ismail-site/voice.md
guides/styling.md                            styling rules, tokens, shared components
styling-guide.md                             full design-system reference
.pi/skills/                                  site-update, site-styling, write-post skills
```

## Commands

Use Homebrew Node (`/opt/homebrew/bin/node`, v20+). A node binary signed by another app can't load `sharp`.

| Command | What it does |
|---|---|
| `npm run dev` | Vite dev server (includes `drafts/`) at http://localhost:5173 |
| `npm run validate` | Content checks (frontmatter, dates, images, internal links) + style guardrails. Fast, so run it often |
| `npm run build` | validate → optimize-images (cached, ~1s when unchanged) → vite build → prerender (per-route OG HTML, 404.html, sitemap.xml, robots.txt) |
| `npm run check:browser -- --out shots/after [--compare shots/before] [--pages /posts/x]` | Real Chrome against `dist/`: desktop 1440 and iPhone 390×844, light and dark. Fails on console errors, failed requests, broken images or links, or horizontal overflow, and saves full-page and fold screenshots |
| `npm run lint:voice -- <post.md>` | Flags AI-sounding patterns in a draft (em dashes, hype words, contrast templates) |
| `npm run optimize-images -- --force` | Rebuild all optimized images from scratch |

`shots/`, `dist/`, `public/optimized/` and `docs/` are git-ignored.

## Definition of done for any change

1. `npm run build` passes. It fails on bad content, style-rule violations, or image errors.
2. `npm run check:browser -- --out shots/after --compare shots/before` reports 0 problems. Take `shots/before` on the base commit first. Any listed visual diff is either intended or explained.
3. For visual changes, show Mohsin the before and after screenshots (desktop and mobile) and wait for his OK before merging.
4. Add `--pages` for any route you touched that isn't in the default list. The defaults are home, blog, about, portfolio, two projects, and five representative posts.

To let Mohsin check on his phone, run `npm run dev -- --host 127.0.0.1` and expose it privately with `tailscale serve`. Never use `tailscale funnel` or any other public exposure.

## Content rules

- Post folder names follow `YYYY-MM-DD-kebab-title`, and the folder name is the URL slug. Never rename a published post, because that breaks inbound links. Folder dates sometimes follow UTC while `date:` is Pacific. Leave those alone.
- Post frontmatter: `title` (required for long posts), `date` (ISO with offset, quoted, e.g. `"2026-03-08T13:20:00-08:00"`), `tags` (lowercase list), optional `type: mini` (no title, short), `enableTableOfContents: true`, and `exclude: true`. `exclude: true` hides the post from the app, prerender and sitemap, but the raw markdown is still publicly copied to `dist/`. Use `drafts/` (git-ignored) for anything private. This repo is public, so never commit drafts or the voice guide.
- Project frontmatter: `title`, `slug`, `date`, `summary`, `tags`, `status`, `cover`, `gallery` (strings or `{src, caption}`), `github`, `live`, and `excludeCoverFromCarousel`.
- Markdown extras: inline footnotes `^[text]`, images `![caption](file.png)` resolved relative to the post folder, attributed quotes `> quote` + `> — Author, *Source*`, fenced code with a language, GFM tables, and YouTube iframes (projects).
- Internal links use clean paths: `/posts/{slug}`, `/portfolio/{slug}`, `/blog`, `/about`, `/portfolio`. Never use `#/` hash routes. Shareable URLs in code use `${window.location.origin}/posts/${slug}`.
- Writing or editing prose: follow the voice guide (`guides/voice.md` locally if present, otherwise `~/.tron/workspace/files/mohsin-ismail-site/voice.md`; it is private and git-ignored, never commit it). Don't rewrite Mohsin's existing posts unless he asks.

## Code conventions and known pitfalls

- Content loading must not crash the site. A malformed file is logged and skipped at runtime, and `npm run validate` fails the build instead. Keep it that way.
- `scripts/content.mjs` is the single Node-side content loader. The prerender and the validator both use it, so they agree with the app on which posts exist.
- State updaters must stay pure, because StrictMode double-invokes them in dev. Hooks must never sit after an early `return`.
- Don't declare components inside render. Embed conditional JSX instead.
- Images: constrain thumbnails with a fixed frame and `object-fit: contain`. On mobile, prefer horizontal row cards over tall grids.
- Third-party snippets go in deferred/async tags with clear placeholders. Remove unused providers.
- The Vite `base` comes from `VITE_BASE_PATH`/`GITHUB_REPOSITORY`. `public/CNAME` forces `/` in CI.

## Agent notes (`docs/`)

The convention is to keep chronological agent notes in `docs/`, which is git-ignored and local only. Files are write-once, named `YYYY-MM-DD HH-MM-SS - Topic.md` (convert the system date to strict Year-Month-Day). To change or revert something, write a new file that references the old one, with a "Diff" and a "Rationale". Past about 50% context usage, suggest a new session and offer a handoff summary.
